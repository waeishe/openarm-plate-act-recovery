# ACTの配置失敗を、追加観測とAgentの復旧で解消できるか

Physical AI応用1 最終課題：プレート搬送と失敗復旧の実装

空の96ウェルプレートをOpenArmで支持台へ搬送するシミュレーションです。学習済みACTが40秒で配置を完了できなかったとき、状態をリセットせずにAgentを呼び出し、追加観測・再把持・置き直しを実行します。

- [全10試行の集計](evidence/results.json) / [判断・操作の時系列](evidence/decision-traces.json)

## 今回の問いと結果

「学習済みACTがプレート配置に失敗したとき、エージェントが追加観測と復旧操作を選んで完了できるか」を、予備探索で選んだ1条件で検証しました。搬送元の支持台とプレートを一緒にx方向へ＋5 mmずらし、同一初期状態でACT単独とACT＋Agentを各5回比較しました。モデル、指示、評価基準を固定し、全試行を120秒の物理時間まで評価しました。過去の探索試行は以下の分母に含めていません。

| 指標 | ACT単独 | ACT＋Agent |
|---|---:|---:|
| 最終2秒間の安定配置 | 0/5 | 4/5 |
| 成功時の復旧物理時間：中央値 | — | 53.5秒 |
| 成功時の復旧実時間：中央値 | — | 181.4秒 |
| 復旧区間の品質合格 | — | 2/5 |
| 全工程の品質合格 | 0/5 | 0/5 |

| 追加試行 | ACT単独 | ACT＋Agent | 復旧物理時間 | 復旧中の品質 |
|---|---|---|---:|---|
| 1 | 未完了 | 完了 | 76.0秒 | 不適合 |
| 2 | 未完了 | 完了 | 64.7秒 | 不適合 |
| 3 | 未完了 | 未完了 | — | 不適合 |
| 4 | 未完了 | 完了 | 18.5秒 | 適合 |
| 5 | 未完了 | 完了 | 42.2秒 | 適合 |

復旧時間は40秒の引き継ぎ後、最終的な安定配置が2秒継続するまでの時間です。中央値・範囲は成功4試行のみから求めます。失敗を0秒や上限時間に置き換えていません。

成功4試行のうち2試行は途中の開放で中央支持の条件を満たしませんでした。これらは自由落下による成功と断定できませんが、品質を満たす復旧とは区別しています。全試行に共通するACT区間には最大6.26 Nの台への接触があり、全工程の品質条件は両方式とも不適合です。

成功例4では置いた後に上へ退避してから横へ移動しました。失敗例3では上昇と横移動が重なり、再接触で配置を崩しました。他の動作も異なるため、退避経路だけの因果効果は未検証です。5組は選んだ同一状態での再現性を示し、多様な配置に対する成功確率を推定するものではありません。ACT側の軌道は5回とも同一でした。

## 実装

`ACT → 40秒で未完了を検出 → 同じ状態でAgentを呼ぶ → 追加観測と操作 → 独立した評価`

- **ACT**：LeRobotのACT実装。2視点RGB（160×128）と16関節の位置から40ステップの動作列を予測し、先頭10ステップを10 Hzで適用。言語入力は使いません。
- **学習**：校正済みスクリプトから20本の成功デモを生成し、4本を検証に使用。初期位置の微小変動は±0.7 mm。3,000＋4,000更新のチェックポイントを固定しました。
- **Agent**：gpt-6-astra、reasoning effort medium。指示を固定し、最大30判断。画像と要求したRGB-Dの推定値、ロボット状態を使って観測・移動・把持・待機を選びます。校正済みIKを使用します。
- **観測**：空の左手先をどけて上方視点の遮蔽を減らします。同じ左腕で復旧します。右腕による能動観測を実証した実験ではありません。
- **評価**：物体の真値と接触力は評価専用です。Agentへの入力に渡しません。最終配置はXY誤差≤3 mm、傾き≤1°、yaw≤3°、高さ誤差≤2 mm、低速度、中央支持、ストッパー荷重≤0.02 N、開いた手先が5 cm超離れていること等を、最終2秒間確認します。判定式は `src/quality.py` と `src/environment.py` にあります。
- **品質**：両指での持ち上げを0.3秒以上、全開放前の中央支持を0.2秒以上確認し、支持なしの把持喪失と0.5 N超の台接触を検出します。復旧区間と全工程を別集計します。

Agentには追加RGB-Dと校正済み操作機能があるため、この比較だけでは言語モデルの推論の効果を分離できません。空プレートのシミュレーションであり、実機や液体入りプレートの安全性は検証していません。

## 実行環境と準備

動作確認済み：Apple Silicon Mac、macOS 26.6.1、Python 3.12.12、MuJoCo 3.15.0、PyTorch 2.11.0 / torchvision 0.26.0、LeRobot 0.6.1。ACTはMPSを使用します。CPU/CUDAへの切り替えや他OSは未検証です。

以下はこのリポジトリ内で実行します。既存のOpenArm環境へのシンボリックリンクや絶対パス参照は不要です。MuJoCo資産、学習済み重み、試行記録を同梱しています。

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -B run.py verify
python -B run.py rescore
```

`rescore` はモデルを呼ばず、全10試行の保存記録から配置・品質・復旧時間を再計算し、元の集計との一致を確認します。依存関係の新規インストールからの検証は行っておらず、上記の既存ランタイムで動作確認しました。

### シミュレーションを実行

```sh
python -B run.py eval --method act --run example-act
```

結果は `runs/example-act/` に作成されます。既存のrun名は上書きしません。

モデルを呼ばずに成功例4の**記録済み判断**で復旧を再生する場合：

```sh
python -B run.py eval --method agent --run example-recorded --recorded-decisions pair-04-agent
```

これは公開パッケージの動作検証・再生であり、新たなAgent実験ではありません。提出前にACT単独とこの再生を実行し、元試行との全3,601フレームのqpos・qvel・ctrl・物理時間、全操作・評価記録の完全一致を確認しました（`evidence/portability.json`）。

### Agentを実際に呼び出す

```sh
python -B run.py eval --method agent --run example-live-agent
```

このコマンドには認証済みのCodex CLIと、記録時と同じモデル・CLI機能へのアクセスが必要です。モデル使用量が発生します。CLIは環境に依存するためrequirements.txtには含めていません。固定したモデル名を別モデルに置き換えると別条件になります。モデル提供・CLI機能が異なる環境での動作は保証していません。

実行中の停止は、対象run内に `STOP` という空ファイルを作成します。生成された `runs/` にはローカルパスやモデル実行ログが入るため、公開対象から除外しています。

### 学習過程を再実行する場合（提出結果の確認には不要）

```sh
python -B run.py demos --count 24
python -B run.py train --name act-v1 --steps 3000 --lr 0.0001
python -B run.py train --name act-v2 --steps 4000 --lr 0.00003 --resume checkpoints/act-v1/step-003000.pt
```

学習時はImageNet初期重みを取得します。再学習した重みのビット単位の一致は保証しません。提出結果には同梱の `checkpoints/plate-act.pt` を使用します。学習データ生成条件・元データのハッシュは `configs/data-plan.json` と `evidence/training-provenance.json` にあります。大容量のデモ画像配列は同梱していません。

## ファイルと再現性

- `src/`：環境・学習・推論・観測・Agent・評価の実装。
- `assets/`：プレートシーンと実際に参照するOpenArmモデル資産。
- `checkpoints/plate-act.pt`：実験で使用した固定重み。
- `configs/protocol.json`：5組の実行順序、上限時間、モデル・指示のハッシュ。
- `evidence/trials/`：全10試行の操作・物理状態・評価・時刻記録（gzip圧縮）、Agentの記録済み応答。
- `evidence/source-provenance.json`：コピー元の相対プロジェクト名、元ファイルと公開ファイルのハッシュ。移植変更の有無を記録。
レポートと動画は課題の指定先に別途提出します。アカウント識別子をコード側へ複製しないため、このコードパッケージには含めていません。
